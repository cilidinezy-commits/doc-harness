# Doc Harness 升级设计提案（首版，供评审；未实施）

> 状态：2026-09-07 初稿。目标是先把方向讲清楚、把关键取舍摆出来，再决定动手。
> 定位红线：doc-harness 只做「过程信息记录 + 检索」，不干预 agent 如何做它的工作。

## 1. 要解决的问题

- 最大威胁 = **session 切换**：切换必然丢信息，新 session 开局必然出错。
- 核心痛点 = **信息量太大、散落在大量文档里，难以判断哪些是当前工作真正需要的**（检索/定向问题），「读了没懂」不是主要矛盾。
- 现状的模型偏差 = 项目被记成「线性阶段 + 线性步骤列表」，但真实进展是**有结构的、可变的、非线性的“面”**。

## 2. 两条主线

### 主线 A：可变的、有结构的「活跃工作面」+ ENTRY/NOW 入口

把“当前状态”从一条模糊的“当前阶段”，改成一个**轻量的工作面**：

- **顶层规划**（A→B→C，可改）→ **各部分/子部分** → **最小工作单元**；
- **活跃前沿**＝当前正在做的少数几个单元（可跨分支、非连续）；
- 结构变化（重排、新增部分、单元收口）被当作“面的变更”记录，而不是无限追加步骤。

在这个工作面之上，提供一个极短的 **ENTRY/NOW 快照**，只回答新 session 最先要的三个问题：

1. 现在在干什么（阶段＋当前工作单元，一两句）；
2. 下一步 #1 与障碍；
3. 恢复第一读＝哪几份文件/锚点（最小清单，不含详情）。

约束：**一屏以内**（硬上限约 20–30 行）；历史一律分离；**每次 session 结束 / compact 前必须刷新**，否则过期入口比没有更危险。

### 主线 B：确定性工具带（tools/）

把各项目手工反复造的机械动作，收成 doc-harness 自带的**可选工具**（脚本/命令 + 使用说明），让机械事不必全由 agent 手做。首批候选：

1. **邮件被动轮询 + 邮件状态账本 + 收尾守卫**：吸收 一个下游项目 开发、一个下游项目 复用的那套。证据核实：轮询脚本（`poll_loop.ps1` / `passive_poll_backoff.ps1`）**只做「检测未读 → 唤醒」**，不更新状态文档；真正处理靠一份一次性 `mail-process-prompt.md` 提示词，其中**显式写了「在 CURRENT_STATUS 车身记录本次交流 + 完成后刷新最后更新」**。所以「处理后更新状态文档」既不是脚本逼的，也不是纯 LLM 自觉，而是**写进处理提示词里的纪律**——但仍缺确定性兜底。doc-harness 化时要补上**确定性收尾守卫**：处理完并 actioned 后，校验 CURRENT_STATUS 的「最后更新」是否真的前进过，没前进就红/提醒——把「靠提示词自觉更新」变成「被守卫兜底」。
2. **未注册文件会红**：确定性检查「新文件不在 FILE_INDEX ⇒ 红」，把 B13 从人记得升级为工具兜底。
3. **嵌套独立项目 git 守卫**：pre-commit 钩子拦截「目录级 `git add` 吞掉自带 CLAUDE.md 的子项目」（B12）。
4. **ENTRY/NOW 快照刷新/校验**：session 结束/compact 前刷新快照；`check` 校验其新鲜度与行数上限。
5. **WORKLOG 归档 / 车身折叠辅助**：按“件”为单位折叠与归档，降低长战役的维护成本（B14）。

定位：给 agent 的**可选机械帮手**；不强制、不指挥 agent 决策。

## 3. 分期建议

- **第一期（命中最高优先级）**：ENTRY/NOW 快照 + 未注册会红 + 邮件轮询/账本。
- **第二期**：工作面模型（层级 + 活跃前沿 + 结构变更记录）+ 其余工具（git 守卫、归档辅助）。

## 4. 待决问题（需要你拍板或我先给默认值）

1. ENTRY/NOW 是**独立文件**（如 `ENTRY.md`），还是 **CURRENT_STATUS 顶部的固定节**？
2. “工作面”的层级/命名（顶层规划/部分/最小单元）是给**默认模板**，还是完全交给项目自定？
3. 工具带是否要**跨平台**（PowerShell + bash 双份），还是先只做当前环境（Windows/PowerShell）？
4. 现有 6 个命令（init/check/sync/flush/recall/resume）里，`resume` 与 `check` 是否应直接接管 ENTRY/NOW 的“读取/校验”职责？

## 5. 明确不做

- 不新增“教 agent 怎么工作”的规则（含不规定是否/何时启动子代理）。
- 不替项目做计划/管理；只记录项目已有的结构。
- 不在本阶段改任何 skill/spec 文件；先评审、后设计、再实现。
