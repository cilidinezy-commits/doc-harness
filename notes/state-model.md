# 状态模型：从「三份手工快照」到「一份事件日志 + 投影」

## 问题的最底层表述

当前 v2.0.0 把项目状态记成三份**手工维护**的东西，靠 conformance 拉平：

- WORKLOG（历史）—— append-only，但只记「已完成的单元」。
- 活跃工作面（结构）—— 手工维护的 `[active]/[done]/[future]` 树。
- `## NOW`（当前快照）—— 手工维护的「在办/下一步/先读/关键判断」。

这三份其实表达的是**同一件事的不同投影**：项目在时间中发生的一系列事实。
于是它们必然漂移（一个下游项目 实测的「复发阈值四处四值」就是同一病根的外显），我只能靠守卫在事后抓漂移。

## 底层逻辑：原语应该是事件，快照是派生

- **原语＝append-only 事件日志**：单元开/激活/收口、面重排、关键判断、下一步变更、先读变更。它线性（时间是线性的），且天然并发安全（只追加、不覆盖）。
- **活跃工作面＝由事件投影出来的结构**（哪些单元存在、处于什么状态）。
- **NOW＝由事件投影出来的当前前沿**（活跃单元、最新下一步、最新判断、最新先读）。

这正好同时满足用户两条哲学判断：
1. 「项目是有结构的面，不是线性序列」——**原语是线性的（事件按时间发生），但投影是结构化的面**；二者不再被混在一个手工文件里。
2. 「接手优先于记录」——接手读的是投影（NOW/面），而投影永远由同一份事件算出，不会和记录分叉。

它也是 doc-harness 自己的「单一事实来源」铁律推到终点的样子：一份事实，一份原语，其余重算。

## 多视角审视（为什么对）

- **记录视角**：最忠实的记录是「发生了什么」的事件流；手工快照是有损投影。
- **检索视角**：NOW/面是快速视图；视图由原语派生，就永远一致。
- **工程视角**：append-only 天然解决 R4 并发写覆盖；解析器只需一个（`Get-DocState` 读事件、投影）。
- **诚实视角**：事件日志天然保留「谁在什么时候把什么改成了什么」，可审计、可回溯。
- **成本视角**：多了一个投影工具，但删掉 14 个 regex 各自解析、以及 conformance 里为了拉平而存在的一大半检查。

## 代价与边界（不回避）

- 需要「投影工具」在读取前把事件投影成 NOW/面——这是新增的一个机械步骤，但它是**确定性、可验证**的，不是让 agent 多记一条纪律。
- 事件格式必须是**扁平、机器可读、人类也可读**的，不能变成第二个 DSL（一个下游项目 的警告）。
- 不因此改变 scope：仍是「记录 + 检索」，投影只是检索的机械实现。

## 事件 schema（首版，扁平一行一事件）

```text
2026-09-07 unit:open      alpha 建模主效应
2026-09-07 unit:activate  alpha
2026-09-07 unit:open      gamma 稳健性检验
2026-09-07 unit:activate  gamma
2026-09-07 judgment:set   "主效应量级对样本选择敏感" source=notes/beta-findings.md
2026-09-07 next:set       "完成 gamma 异方差稳健标准误" blocker=none
2026-09-07 read-first:set [notes/beta-findings.md, WORKLOG.md]
2026-09-07 unit:close     beta evidence=notes/beta-findings.md
```

投影规则：
- **活跃前沿**＝所有发生过 `activate` 且未 `close` 的单元。
- **面**＝`open` 建立单元 + `close` 标记 `[done]` + `activate` 标记 `[active]`；未 `activate` 的为 `[future]`。
- **NOW**＝最新一条 `next` / `judgment` / `read-first` / 最新 `activate` 集合。
