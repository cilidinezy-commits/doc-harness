# 深入分析（在等回信期间，暂不动手）

## 1. 真正的「原语」也许不是 NOW/工作面，而是事件日志

现在 v2.0.0 有三个**手工维护、需要靠 conformance 拉平**的视图：WORKLOG（历史）、活跃工作面（结构）、NOW（当前快照）。
它们其实是同一件事的三个投影。把它推到逻辑终点：

- **事件日志是原语**（append-only：单元开/关、面变更、关键判断、收口）。
- **活跃工作面 = 由事件投影出来的结构**。
- **NOW = 由事件投影出来的当前前沿**。

这样一来，「前置字段 vs NOW 散文两个真相源」「并发写覆盖」这些病根都会消失——不是「两份同步」，而是「一份原语、其余重算」。一个下游项目 的 R4 完整版（append-only 事件日志）和「枚举源不取副本」其实都在指向这里，但我一直没敢碰这个根本重构，只在外面打守卫。

## 2. doc-harness 真正的产品是「接手契约 + 验证器」，不是文件

文件只是材料；真正要交付的是：

> 一组不变量，只要成立，就能保证「零上下文 agent 只读入口即可正确接手」；以及一组验证这些不变量的守卫。

把「五文档 + 14 工具」收敛成一份**很小的不变量清单**（NOW 真实/完整/不陈旧/指针可解析/纪律有归宿/文档可反证），工具只是每条不变量的验证器。conformance 也就有了真正含义：**逐条证明每条不变量都被某个验证器覆盖**。

## 3. 「该红·量不到」推广成「地图要诚实，而不是答案要完整」

lit 的两句合起来：诚实是地图的性质、不是答案的性质；该红·量不到是「诚实地说我量不到」。
所以 doc-harness 不该假装「全部可验证」，而该**把验证状态本身记清楚**：哪些有守卫、哪些是盲区、哪些靠自动注入、哪些只是可查。这才是「不丢不假」之上的更高一层：**不假装**。

## 4. 边界线比「陈述句 vs 疑问句」更准的表述

疑问句只是症状。更稳的线是**人称/来源**：

- **第一人称状态**（agent 记录自己：在做什么、下一步、判断）——doc-harness 该记。
- **第三人称项目事实**（关于项目对象的声明，可验证）——锚/铁律该记。
- **第三人称教练规则**（「你应该怎么想/怎么做」）——不属于状态，doc-harness 不提供模板。

「下一步」是 agent 自己的状态（第一人称），所以合法；「下结论前问自己」是教练（第三人称指令），所以越界。

## 5. 「正确接手」能否形式化

试给一个可检验的表述：

> 存在一条有界读取序列 E（身份→稳定锚→NOW→先读），使得一个零上下文 agent 读完 E 后，能重建「当前前沿 + #1 下一步 + 关键判断 + 其来源」，且 E 中每个引用都可解析、无歧义。

「正确」的充要条件＝NOW 同时满足：真实（反映现实）、完整（覆盖活跃前沿）、不陈旧、指针可解析。四条各对应一个守卫，conformance 的任务就是证明四条都被覆盖且无重叠缺口。
