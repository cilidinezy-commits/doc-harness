# doc-harness v2 核心设计（草案，已做关键取舍）

> 依据：`notes/foundational-analysis.md` 的 F1–F6 与 R1–R5。定位红线不变：只做记录 + 检索，不干预 agent 工作方式。

## 一句话

把「仅凭文件正确接手」落实为：**唯一入口 + 一屏 NOW + 稳定锚层 + 结构化活跃工作面 + 确定性校验 + 可选工具带**。

## 文档模型（五个角色）

- **CLAUDE.md** ＝ 唯一入口 + 稳定锚层（框架锚 / 铁律 / 底层原则，编号，每条指向全文落档处）。
- **AGENTS.md** ＝ 薄指针，只指 CLAUDE.md（根治 F1 的入口分裂/双读）。
- **CURRENT_STATUS.md** ＝ 顶部一个 **`## NOW` 块**（一屏内）＋下方「活跃工作面」＋历史车辙（指向 WORKLOG，不进 NOW）。
- **WORKLOG.md** ＝ 历史（只增不改；归档仍用 1000 行阈值，但按「件 / 单元」为单位折叠）。
- **FILE_INDEX.md** ＝ 文件目录，配「未注册会红」的确定性检查。
- 可选：`PHILOSOPHY.md`（底层原则全文）、`PARKING_LOT.md`、`RUNBOOK.md`（运维续跑）、`MAIL_LEDGER.md`（消息账本）。

## NOW 块（核心；已定取舍）

- **位置**：CURRENT_STATUS.md 顶部固定节 `## NOW`（不新建独立文件，避免入口再分裂）。
- **内容**（每项一至两行）：
  - **在办**：当前活跃工作单元（编号/名称，最多 2–3 个，可跨分支）。
  - **下一步**：`#1` 行动 + 障碍。
  - **先读**：最小恢复读清单（2–4 个文件/锚点）。
  - **关键判断**：最近一次改变方向/优先级的判断（可选，但重要）。
  - **刷新**：最后更新时间。
- **硬约束**：≤ 一屏（约 20–30 行）；历史不入 NOW；session 结束 / compact / 阶段切换前刷新。
- **接管**：`resume` 第一读 `## NOW`；`check` 校验 NOW 的新鲜度、行数上限、编码。

## 稳定锚层（CLAUDE.md 顶部，很少变）

- **框架锚**：项目分几层 / 当前做哪几层 / 责任边界 / 北极星红线（只在真架构变动时改）。
- **铁律**：项目级规则。
- **底层原则**：编号的「生成原则」（能推出做法的那些），每条指向 PHILOSOPHY/设计文档全文。
- 作用：跨 session 必带；与易变的 NOW 严格分离（对应 lit 的「11 条底层逻辑清单」）。

## 活跃工作面（替代「单一阶段 + 线性步骤」）

- 记录当前项目的「面」：顶层规划（可改）→ 部分 → 最小工作单元。
- **活跃前沿**＝当前正在做的少数单元；`NOW` 的「在办」就是这个前沿的当前切片。
- 结构变更（新增 / 重排 / 单元收口）记录为「面的变化」，而非无限追加步骤。
- 默认给轻量模板，允许项目覆盖；只记录现实结构，不做计划/管理。

## 确定性工具带（可选，`tools/`）

- **邮件轮询 + 状态账本**：吸收 两个下游项目 的轮询 + MAIL_LEDGER；补「处理后校验 NOW 是否前进」守卫。
- **未注册会红**：`check` 增强为确定性红项。
- **嵌套项目 git 守卫**：pre-commit 拦截吞掉自带 CLAUDE.md 的子项目。
- **NOW 刷新 / 校验**：session 结束/compact 前刷新；校验新鲜度/行数/编码。
- **WORKLOG 归档辅助**：按「件 / 单元」折叠与归档。
- 首批只做当前环境（Windows/PowerShell）；跨平台后续再说。

## 明确不做

- 不规定 agent 是否/何时启动子代理；不规定 agent 怎么想、怎么做。
- 不做计划/管理；只记录项目已有的结构。
- 不把「子代理」写成给 agent 的行为规则（v1.7.2 那处要回退/重定位）。
