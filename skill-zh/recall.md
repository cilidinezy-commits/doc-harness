# Doc Harness — 信息召回

从项目的 Doc Harness 文档中检索信息。只读；每个声明都要引用来源。

机械 grep 用 `tools/search.ps1`（层：`all` / `now` / `history` / `files` / `anchor`）；`recall` 是在其上的综合协议。

## 查询类型

| 类型 | 含义 | 主要层级 |
|------|------|----------|
| A. 状态 / 计划 | 「下一步？」「当前状态」 | NOW + 活跃工作面 |
| B. 历史 / 决策 | 「为什么 / 何时 / 谁决定」 | `events.log`（按 unit-id / 动词 / 日期 grep） |
| C. 文件 / 主题查找 | 「找关于 X 的文件」 | FILE_INDEX |
| D. 综合 | 「关于 X 的一切」 | 全部层级 |

不明确 → 默认 D。

## 分层搜索（自上而下，提前停止）

- **第 0 层**：`CLAUDE.md` —— 稳定锚（框架锚、铁律、底层原则）。
- **第 1 层**：`CURRENT_STATUS.md` —— 先 `## NOW`，再看活跃工作面 / 近期历史。
- **第 2 层**：`events.log` —— 历史在这里，一行一条状态变更。grep 它（按 unit-id、动词或日期）；CURRENT_STATUS 里的工作面就是它的可读目录。不要从头到尾读。
- **第 3 层**：`FILE_INDEX.md` —— 只 grep；递归子索引。
- **第 4 层**：单个文件 —— grep + `-C 3`；全文读只作最后手段。

## Token 效率规则

1. 上下文优先：先看答案是否已在对话上下文中。
2. 先 grep 再读。
3. 绝不全文读大文件：`events.log` 只 grep（按 unit-id/动词/日期）；FILE_INDEX >50 行 → grep；任意文件 >100 行 → grep + 上下文。
4. 子索引用 grep，不全文读。
5. 每个声明都引用：`(CURRENT_STATUS.md ## NOW)` 或 `(notes/design.md#L42)`。
6. 「未找到」可接受——不要幻觉。
7. 一旦答完就提前停止。
8. 范围限制：>10 个匹配 → 显示前 5 个并请缩小范围。

## 输出格式

```
═══════════════════════════════════════
  Doc Harness — 信息召回
  查询: ...   类型: A|B|C|D   层级: 0–N
═══════════════════════════════════════
── 第 0 层: 稳定锚 ── ...
── 第 1 层: NOW / 活跃工作面 ── ...
── 第 2 层: 历史 ── ...
── 第 3 层: 索引匹配 ── ...
── 第 4 层: 文档详情 ── ...
── 综合 ── [答案，每个声明有引用]
── 未找到 / 漂移备注 ── [如有]
═══════════════════════════════════════
```

recall 是只读的：记录漂移但不修复（`sync` 修复；`check` 报告）。
