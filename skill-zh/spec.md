# Doc Harness — 完整规范

**版本**: v2.0.0
**日期**: 2026-09-07
**状态**: v2 生产设计

## 1. 目的与范围

Doc Harness 让项目仅凭文件即可恢复：任何 session 断裂或上下文压缩之后，一个全新 agent 都能通过读入口文档正确接手。

**它回答的唯一问题**：在「session 必然结束、上下文必然丢失」这一不可动摇的前提下，项目状态的最小、可信表示是什么，才能让新 agent 正确接手？

**范围**：Doc Harness 记录过程信息并帮助检索/定向。它**不规定** agent 怎么做工作（没有「用子代理」「这样想」之类的规则）。

**核心原则——接手优先于记录**：写是手段，正确接手才是目的。不写 = 丢失；从入口找不到 = 等同丢失。

## 2. 文档

### 2.1 CLAUDE.md —— 唯一权威入口

按序包含：

1. **AGENT IDENTITY LOCK**（顶部）：agent 是谁、职责范围；自检。
2. **稳定锚**：框架锚、铁律、底层原则。
3. **一句话状态**（唯一允许的冗余）。
4. **恢复链**（必读 + 任务条件读）。
5. **项目概述 / 关键技术信息**。
6. **操作规则**（嵌入在 `<!-- doc-harness-ops-start -->` 与 `<!-- doc-harness-ops-end -->` 之间；该区域带 `<!-- doc-harness-ops-version: N.N -->`）。

### 2.2 AGENTS.md —— 薄指针

若存在，是几行指向 `CLAUDE.md` 的指针。绝不承载分叉的状态副本。两份分叉入口文件会造成过时状态与部分 harness 的双读重复注入。

### 2.3 CURRENT_STATUS.md —— 生成投影

`## NOW` + 活跃工作面 + 近期历史，由 `tools/project.ps1` 从 `events.log` **投影**出来。它是派生视图，绝不手工编辑。

### 2.4 FILE_INDEX.md —— 目录

按类别组织文件。未注册文件在 `check` 中是红（失败）项。

### 2.5 events.log —— append-only 事件日志（原语）

一行一条结构化事件（`<日期> <动词> <载荷>`）。它是历史与当前状态的**单一来源**；投影（§2.3）由它导出。v1 时期的散文工作日志可移入 `_archive/` 作为历史参考保留。

## 3. NOW 块（规范性）

`## NOW` 是项目的**当前快照**——恢复时读锚之后的第一读。它不是历史。

精确格式（字段名即契约——英文、ASCII，且**由工具生成**，绝不手写）：

```markdown
## NOW

- **Active**: `<unit-id>`, `<unit-id>`   （1–3 个 = 活跃前沿；空则 `(idle)` / `(paused)`）
- **Next**: `#1 行动` — 障碍: `...`
- **Read-first**: `<路径>, <路径>`       （2–4 个指针，按序）
- **Key-judgment**: 一句话（最近的方向/优先级变化）—— `source=<路径> class=...`
- **Refreshed**: `YYYY-MM-DD`
```

字段语义：

- **在办**：当前 1–3 个活跃工作单元。每个是存在于活跃工作面（§5）中的稳定 `unit-id`。所有未收口单元都挂起时渲染 `(paused)`，没有任何在办单元时渲染 `(idle)`。
- **下一步**：唯一最高优先级行动，始终配障碍（或「无」）。
- **先读**：最小接手清单——只指向具体文件/锚点，按阅读顺序。
- **关键判断**：可选但高价值——一条会重新定向工作、又易丢的近期结论。存在时**必须带来源指针与 class**（`source=<路径> class=root|decision|reported`）；投影原样携带，`tools/cite-check.ps1` 强制校验。
- **最后刷新**：由**最后一条事件**的日期投影而来——所以*记录事件就是刷新 NOW*。没有新事件的项目保留旧日期是正确的；`tools/now-verify.ps1` 会把这个日期与项目文件的最新改动对比，抓出「做了工作却没记录」。

约束：

- ≤ 约 30 行（一屏）。历史不得泄进 `## NOW`。
- session 结束、compact 前、活跃前沿变化时刷新。
- **在办** 是「当前正在做什么」的唯一住处。活跃工作面的 `[active]` 标记与其镜像，`check` 校验两者一致。
- `check` 校验新鲜度/行数/编码；`resume` 先读它；`flush` 最后刷新它。

机器可读前置信息（工具的唯一数据源）。`CURRENT_STATUS.md` 以 YAML 开头：

```yaml
---
now_refreshed: YYYY-MM-DD
active_unit_ids: [unit-a, unit-b]
read_first: ["path/to/a.md", "path/to/b.md"]
---
```

工具读字段、不读散文：`now_refreshed` 是新鲜度的权威；`active_unit_ids` 必须等于活跃工作面的 `[active]` 集合；`read_first` 路径必须存在（`tools/dead-pointer.ps1`）。

## 4. 稳定锚（规范性）

锚承载很少变化、必须跨越每次 session/compact 的东西：

- **框架锚**：项目如何分层、当前做哪几层、责任边界、北极星红线。
- **铁律**：与项目同寿的规则。
- **底层原则**：只放**项目域事实的陈述句**（如「有一个叫 X 的守卫 ≠ X 真守住了它」），每条指向全文落档处（`PHILOSOPHY.md` 或设计文档）。agent 操作约定（「该怎么想」「下结论前问自己」）**不**放这里——那是教练、不是状态；只在项目自己要时放进 `PHILOSOPHY.md`。

锚只在真架构变化时改，不随 session 变。

## 5. 活跃工作面（替代线性「阶段」）

把当前工作记成**可变、有结构的面**，而非线性列表。

格式（投影后的样子）：

```markdown
## Work Surface

### Plan
- <部分>
- <部分>          （每个顶层部分一条；`plan:set` 的载荷按 `|` 或 `->` 切分）

### Units
#### <部分>                          （仅当 unit-id 采用 `部分/单元` 形式时出现）
- [active] `<unit-id>` 描述
- [future] `<unit-id>` 描述
- [done] `<unit-id>` 描述
- [paused] `<unit-id>` 描述
```

规则：

- `unit-id` 是稳定、项目自选的标识（如 `F49`、`C/出口对账`），被 `## NOW` 引用。`[active]` / `[done]` 单元应带指向其证据的来源指针。
- `unit-id` 不含空格（解析器按第一个空格切分 `unit:open <id> <描述>`）。**结构可以白拿**：写成 `C/出口对账`，工作面就会把它归到 `#### C` 之下。扁平 id 依然合法、渲染为平铺列表——项目可以一直扁平，直到它真的分叉。
- 状态标记：`[active]`（前沿）、`[future]`（未开始）、`[done]`（已收口，其 close 事件携带证据）、`[paused]`。
- 结构变化（新增部分/重排/单元移动/单元收口）是**面的变更**——原地编辑面，不追加线性历史。
- 优先做**差量编辑**（增/删/改一个单元），而非整段重写活跃工作面。
- 面记录现实，不做计划。部分/单元存在于此，是因为项目真的拥有它。

非冗余：面持有结构 + 状态；`## NOW` 持有当前焦点；`events.log` 持有历史与已完成单元细节。`check` 校验 NOW 的在办单元与面的 `[active]` 标记一致。

**原语**：`## NOW` 与活跃工作面是**从 append-only 事件日志（`events.log`）投影出来**的，不是手工维护。agent 追加事件；`tools/project.ps1` 通过确定性回放导出视图。事件 schema（一行一条）：`<日期> <动词> <载荷>`，动词 ∈ `unit:open` / `unit:activate` / `unit:close` / `unit:pause` / `next:set` / `judgment:set` / `read-first:set` / `plan:set` / `dead-end:set` / `note:set`。以 `#` 开头的行是注释，回放时跳过（日志借此携带自己的表头与说明）。回放是机械的（无语义）：散文（描述、判断）在写时产生，读取时原样携带。

投影的版面：`## NOW` → `## Work Surface`（`### Plan`、`### Units`）→ `## Recent History (closed units)` → `## Notes (housekeeping)` → `## Dead ends (negative ledger)`。Notes 带记录日期，只渲染最近若干条（其余留在日志里）；它存在的理由是：一次 ops 重新嵌入、一次 schema 迁移、一次守卫修复——这些改变了状态文档却既不是单元、也不是判断、也不是计划——必须**可记录**，否则时效守卫会永远红着。

**Schema 迁移**（接手一个早于某次 schema 变更的项目——例如 `class=` 成为必填之前写下的收口/判断）：只增不改是*记录*的规则；一次性 schema 迁移是刻意的重写，因此必须可审计，不能靠手改：

1. `tools/log-migrate.ps1` 把迁移前的日志归档到 `_archive/events-pre-migration-<date>.log`（作为证据），规范化事件，并在日志里留一行 `#` 注释说明迁移了什么、旧日志在哪。
2. 迁移不得改变投影（注释回放即空操作）；用 `tools/conformance.ps1` 验证。
3. 在 FILE_INDEX 注册归档，并把这次迁移记入项目自身历史（`judgment:set … source=<归档> class=decision`）。

迁移绝不凭空造证据：完全缺 `evidence=` 的收口会被报告出来由人/agent 解决，而不是猜测填补。

## 6. 放置、可反证与复发（写下来 → 用起来 → 是真的）

写下来不等于**用起来**，用起来也不等于**是真的**。每条纪律/规则/教训都要声明放置，每份文档都要能被机器反证。

四个放置状态：

| 状态 | 含义 | 判据 |
|------|------|------|
| **会红（Gate）** | 有真存在的守卫 | 违反时变红 |
| **该红·量不到** | 原则上可验，但现有量具的形状够不着 | 记为有名有姓的盲区 |
| **自动注入（Auto-inject）** | 变不成守卫、但每次都要在场 | 住在 CLAUDE.md 顶部 |
| **可查（Queryable）** | 详情与来龙去脉 | 当前文档 |

放置规则——写一条纪律前先问「**机器看得见它吗？**」（不是「能不能验」）：

- 能且可测量 ⇒ 做成守卫。
- 原则上能、但没有量具 ⇒ 标 `该红·量不到`（记成有名有姓的盲区，这是它「缺席」唯一可见的方式）。
- 不能 ⇒ 必须住进自动注入层，且短到真的能被读完。
- 只写进可查层，是明确承认它可能丢。

**可反证（「是真的」这一层）**：每份文档配一个会红的对偶——**枚举源取原文，不手抄**（同一事实写两处必分叉），并**验证它指名的每个文件/编号/数字现在还在**。`check` 问：「这份名单是抄来的还是算出来的？」「它指名的每样东西现在还在吗？」

**时效**有两面，两面都会红：

- *常设结论*（稳定锚、PHILOSOPHY、设计文档）带机器可读的 `conclusion_until: YYYY-MM-DD` 与 `verify_via: <命令或路径>`。`tools/stale-check.ps1` 把过期结论标为超期——治「过期的结论写得像现行」。
- *状态本身*可能根本没被记录。`tools/now-verify.ps1` 把 `now_refreshed`（最后一条事件的日期）与项目自有文件的最新改动对比；比最后事件更新的工作即**红**（「做了工作，状态没记」）——这正是 session 切换会让它永久丢失的那种损失。

**溯源**：每个来源指针带一个 class——`root`（可在真数据结构 / 真跑一次 / 代码处验证）、`decision`（陈述性决定）、或 `reported`（二手表态）。无来源、或来源无 class 的声明会被标红。守卫查「有没有活的根」，不查「根对不对」。早于本约定的项目一次性迁移（§5 Schema 迁移），此后只向前：新事件必须带 class。

**复发**：一条纪律被重申，本身就是信号。**第 2 次**就该逼问「为什么它还是靠记得的纪律」，别等第 3 次。重申时记录 `第 N 次（上次: <ref>）`，并加必填的**同形**字段：「这条和册子上哪一条是同一个形状？」（或「新形状——哪里新」）。工具算不出同形，但能强迫人回答。`check` 报告**重申 ≥2 次、却仍标可查**的纪律。

## 7. 入口唯一

- `CLAUDE.md` 是唯一权威入口。
- 若有 `AGENTS.md`，是薄指针。
- 每个事实只住一个文档。一句话状态是唯一允许的冗余；冲突时以 CURRENT_STATUS 为准。

## 8. 命令

### 8.1 `/doc-harness init`

创建文档（见 `init.md`）：CLAUDE.md（身份 + 锚 + 恢复链 + 嵌入规则）、AGENTS.md 薄指针、CURRENT_STATUS（由 `events.log` 生成）、FILE_INDEX、`events.log`。`DOC_HARNESS_SPEC.md` 为可选参考，非状态。中途采纳忠实重建现实。

### 8.2 `/doc-harness check`

审计：NOW 新鲜度/行数/编码、未注册文件（红）、入口唯一、`events.log` 良好性、收件箱、操作规则版本、身份锁；然后反思锚与底层原则。

操作规则版本取 CLAUDE.md 内的 `<!-- doc-harness-ops-version: N.N -->` 标签，与 `spec.md` 的 `**版本**` 行比对。

### 8.3 `/doc-harness sync`

修复漂移：注册文件、刷新 `## NOW` + 日期、向 `events.log` 追加缺失的状态事件、收件箱整理。交互（默认）在状态变更前询问。

### 8.4 `/doc-harness flush`

紧急保存：sync，然后**强制**盘点上下文（阶段 B）、写入并注册提取项（阶段 C）、验证新 agent 能找到（阶段 D）、最后刷新 `## NOW`（阶段 E）。省略 B/C 即冲刷失败。

### 8.5 `/doc-harness recall`

只读检索：第 0 层锚 → 第 1 层 `## NOW`/活跃工作面 → 第 2 层 `events.log`（历史）→ 第 3 层 FILE_INDEX → 第 4 层文件。每个声明都引用。

### 8.6 `/doc-harness resume`

结构化、可验证的接手：身份 → 稳定锚 → `## NOW` → 先读清单 → 恢复报告 → 5 问验证 → 继续/等待决策。

## 9. 确定性工具带（可选）

doc-harness 可附带 `tools/` 目录，提供可选确定性帮手，让机械记账不必依赖 agent 记得做：

- **状态**：事件追加（`record.ps1`——追加、重投影、跑 conformance；`-EventsFile` 可一次记一批）、投影（`project.ps1`）、投影/版本/ops 嵌入一致性（`conformance.ps1`）、分层检索（`search.ps1`）。**单解析器不变量**：从 `events.log` 重建状态只发生在**一处**（`lib/doc-state.ps1` / `Get-DocState`）；其它工具可以把日志当**文本**读（检索、迁移、遥测），但绝不重新实现回放。
- **真伪**：未注册红、死指针、编码、复发、溯源 class（`cite-check`）、常设结论时效（`stale-check`）、投影陈旧、NOW 结构 + 未记录的工作（`now-verify`）。
- **协作**：发信（`mail-send.ps1`）、只唤醒的轮询（`mail-poll.ps1`）、完备后台守护（加锁/状态/崩溃恢复 + 可选处理进程，`mail-daemon.ps1`）、账本；运行时产物一律落在 `_runtime/`。
- **卫生**：嵌套项目 git 守卫（pre-commit）、并发写守卫、批量注册、遥测、入口唯一（`entry-check`——必须带身份锁，且 `AGENTS.md` 不得长成第二个入口或第二份状态副本）、skill 一致性（`skill-consistency`——两版必须共用同一骨架，**且**任何文档都不得在非迁移语境里重新教回已被淘汰的 v1 模型；所有这些过去都只靠人眼评审）。

这些是帮手，不是对 agent 的命令；是否使用可选。

## 10. 可选文档

- `PHILOSOPHY.md` —— 来自实践的底层原则。
- `PARKING_LOT.md` —— 暂缓事项，含复活前置条件。
- `RUNBOOK.md` —— 运维重启/续跑状态（区别于文档状态）。

## 11. 跨项目通信（inbox/outbox）

可选；存在 `inbox/` 与 `outbox/` 即启用。

- 接收：读未读 → 处理 → `actioned`；除 status 字段外不改。
- 生命周期：`unread → read → actioned → awaiting-reply → closed`。处理后产生了回复（或来信明确期待回复）的消息置 `awaiting-reply`；线程结束置 `closed`。`check` 可标记超过项目自设期限仍未关闭的 `awaiting-reply`。
- 发送：`YYYY-MM-DD-from-<来源>-<主题>.md`，YAML `from/to/date/subject/status/priority`；写本项目 `outbox/` 并复制到收件方 `inbox/`；快照优于指针。
- 发送前自检：正确的 `from`、正确的 outbox、收件方 inbox、未改收件方文档、协议已启用、**收件方能在不了解我的上下文的情况下读懂**（快照优于指针）。
- 消息量大时，可选 `MAIL_LEDGER.md` 记录谁/何时/状态/待回。
- 畸形消息 → `inbox/_malformed/` 隔离。

## 12. 反模式

| 反模式 | 正确做法 |
|--------|---------|
| 历史泄进 `## NOW` | NOW 只放当前；历史进 `events.log` |
| 手改 `CURRENT_STATUS.md` | 它是投影：记事件、重投影（`tools/record.ps1`） |
| 手改 `events.log` 以适配新 schema | 一次性迁移 + 归档 + 注释轨迹（`tools/log-migrate.ps1`） |
| 用散文（工作日志）记录状态 | `events.log` 一行一条状态变更；散文住在它描述的那份文档里 |
| 两份分叉入口 | CLAUDE.md 权威；AGENTS.md 薄指针 |
| 未注册文件被忽视 | `check` 红 + `sync` 注册 |
| 用线性「阶段」记分叉项目 | 活跃工作面 + 活跃前沿（结构靠 `部分/单元` id） |
| 规定 agent 怎么做工作 | 只记录 + 检索 |
| 守卫在健康项目上误报 | 守卫必须红得可行动；误报摧毁信任（`now-verify` 对比真实文件改动，而非日历） |

## 13. 接手保证与验证

当且仅当一个零上下文 agent 只按以下顺序读取：

1. `CLAUDE.md`：AGENT IDENTITY LOCK → 稳定锚
2. `CURRENT_STATUS.md`：`## NOW`
3. NOW 的先读清单命名的文件

...就能在不读任何其他东西的情况下说出：身份/范围、活跃前沿、#1 下一步 + 障碍、最近的键判断、以及接下来要读的文件——这次接手才算正确。

验证分确定性与判断两半：

- **确定性的一半**——`tools/now-verify.ps1` 校验「上手阅读」所依赖的结构不变量：`## NOW` 块存在且有界（≤30 行）、文件是有效 UTF-8、有刷新标记、下一步与先读非空且先读的每个路径都能解析、以及最后一条事件之后没有任何项目文件被改动。`tools/conformance.ps1` 把它与其他守卫一起当作单一闸门运行。
- **判断的一半**——**模拟**：用一个非平凡分叉状态的项目，只读上述三项，把恢复出的状态与真值对照。只有读者能验证「散文说的是不是它想说的」；工具验证的是「它在那里、是新的、彼此一致」。
