# 状态文档体系——操作规则

<!-- doc-harness-ops-start -->
<!-- doc-harness-ops-version: 2.0.0 -->

> 本节嵌入项目 CLAUDE.md，是「仅凭文件即可正确接手项目」的操作手册。权威规范见已安装 skill 的 `spec.md`（非项目本地副本）。
> HTML 注释 `doc-harness-ops-start` / `doc-harness-ops-end` 界定嵌入区域——重新嵌入与 `check` 依赖它们安全定位替换。两者均不得删除。

## 首要原则：「接手优先于记录」

目标不是「写得多」，而是**一个新 agent 在上下文断裂后，仅凭文件就能正确接手**。写是手段，正确接手才是目的。不写=丢失；从入口找不到=等同丢失。

## 入口唯一

- `CLAUDE.md` 是 agent 的**唯一权威入口**。
- 若存在 `AGENTS.md`，它必须是**薄指针**（几行，指向 CLAUDE.md），绝不能是过时副本。两份分叉的入口文件会造成过时状态，以及部分 harness 双读导致的重复注入。

## 稳定锚层（CLAUDE.md 顶部）

很少变化、必须跨越每次 session/compact 的东西：

- **框架锚**：项目如何分层、当前做哪几层、责任边界、北极星红线。
- **铁律**：与项目同寿的规则。
- **底层原则**：编号的「生成原则」，每条指向全文落档处——那几条能推出许多具体做法的原则。

只在真架构变动时改锚，不随 session 变。

## 写下来 → 用起来 → 是真的（放置、可反证与复发）

每条纪律/规则/教训都声明放置：

- **会红（Gate）**：有真存在的守卫。写之前先问「机器看得见它吗？」。
- **该红·量不到**：原则上可验，但现有量具够不着——记为有名有姓的盲区。
- **自动注入（Auto-inject）**：每次都要在场 → CLAUDE.md 顶部，短到能被读完。
- **可查（Queryable）**：详情 → 四文档。

可反证：不要手抄一份必须保持同步的名单；验证每个指名的文件/编号/数字仍存在（`tools/dead-pointer.ps1`）。

复发：**第 2 次**重申就逼问「为什么它还是靠记得的纪律？」。记录 `第 N 次（上次: <ref>）` + 必填同形字段。`check` 报告 ≥2 次重申仍可查。

## NOW 块（CURRENT_STATUS 顶部）

固定节 `## NOW`，是恢复时第一读。**约 20–30 行以内。** 含：

- **在办**：当前 1–3 个活跃工作单元（可跨分支，不是单一线性的下一步）。
- **下一步**：`#1` 行动 + 障碍。
- **先读**：最小接手清单（2–4 个文件/锚点），不是全景地图。
- **关键判断**（可选但重要）：最近一次改变方向/优先级、重新定向工作的判断。写时必须带 `source=<路径> class=root|decision|reported`——投影原样携带，`cite-check` 强制校验。
- **最后刷新**：由最后一条事件的日期投影而来——**记录事件就是刷新 NOW**。

session 结束、compact 前、活跃前沿变化时刷新 `## NOW`。历史绝不进 `## NOW`。

## 活跃工作面（替代线性「阶段」）

把当前工作记成**可变、有结构的面**，而非线性序列：

- 顶层规划（可改）→ 部分 → 子部分 → **最小工作单元**。
- **活跃前沿**＝当前正在做的少数单元；`## NOW` 显示这个前沿的当前切片。
- 结构变化（新增部分 / 重排 / 单元收口）记为**面的变更**，而非无限追加的线性列表。

这是记录现实，不是替项目做计划。

## 核心文档

| 文档 | 职责 | 更新时机 |
|------|------|---------|
| **CLAUDE.md** | 唯一入口 + 稳定锚 + 铁律 + 本规则 | 架构变化时改锚；每 session 刷新一句话状态 |
| **AGENTS.md** | 指向 CLAUDE.md 的薄指针（绝不是状态副本） | 几乎不变 |
| **CURRENT_STATUS.md** | 由 events.log 生成投影（绝不手工编辑） | 经 `project.ps1` 重新生成 |
| **FILE_INDEX.md** | 按类别索引文件 | 创建/删除文件时 |
| **events.log** | append-only 事件日志（原语：历史 + 状态） | 每次状态变化（open/activate/close/pause/next/judgment/read-first/plan/dead-end） |

## FILE_INDEX.md 规则

- 按类别（`##`）组织，不按时间。
- 每条：`路径` — 一句话说明。
- 类别 >20 文件 → 建子索引。
- **注册不是可选项**：未注册文件等同丢失。`check` 把未注册文件报为**红项**。

## events.log 规则

- 一行一条结构化事件：`<日期> <动词> <载荷>`；动词 ∈ `unit:open/activate/close/pause`、`next:set`、`judgment:set`、`read-first:set`、`plan:set`、`dead-end:set`、`note:set`。以 `#` 开头的行是注释，回放时跳过。
- `note:set <文本>` 记录「改了状态文档、却既不是单元也不是判断也不是计划变更」的杂务（ops 重新嵌入、schema 迁移、守卫修复）。没有它，这类工作无从记录，而时效守卫会（正确地）一直报它未被记录。
- 只增不改；投影是对这份日志的确定性回放。
- 状态变化时追加对应事件；`project.ps1` 重新生成 CURRENT_STATUS。记录状态的代价就是一行——所以「留着不记」永远没有正当理由。
- 收口单元的载荷带证据与 class：`unit:close <id> evidence=<路径> class=root|decision|reported`；关键判断带 `source=<路径> class=...`。
- 不需要例行归档：日志每次状态变更才加一行。若真超过约 5000 行，压缩是**保持投影不变的改写**，不是裁剪（见规范「events.log 压缩」）。

## Session 开始 / 恢复

1. 读 CLAUDE.md 顶部 **AGENT IDENTITY LOCK**，声明自己是谁、职责范围。
2. 读**稳定锚**（框架锚、铁律、底层原则）。
3. 读 `## NOW`（在办、下一步、先读、关键判断）。
4. 只读 `## NOW` 的「先读」清单指向的任务条件文件。

若上下文为空或用户说「恢复」，执行 `/doc-harness resume` 把以上步骤**显式且可验证**地做一遍。

## 工作过程中

- 完成一个**有意义的单元** → 向 `events.log` 追加 `unit:close` 事件（带证据）并重新投影 `## NOW`。
- 创建文件 → **立即**注册 FILE_INDEX。
- 重要信息 → 现在写下来。
- 关注剩余 context：降到 ~<20% 时，在下一次工具调用前刷新 `## NOW`。压缩即非自愿 session 结束。

## Session 结束检查清单

- [ ] `## NOW` 反映了当前在办/下一步/先读/关键判断？
- [ ] `## NOW` 的「最后刷新」已更新？
- [ ] CLAUDE.md 一句话状态已刷新？
- [ ] 新文件已注册 FILE_INDEX？
- [ ] 收口的工作单元在 `events.log` 里有 `unit:close` 事件？
- [ ] 还有只存在于 context 的信息？→ 落笔为安。

## 确定性工具带（可选）

doc-harness 可附带 `tools/` 目录，提供可选确定性帮手，让机械记账不必依赖 agent 记得去做：

- **一步记录**（`record.ps1`）：追加事件、重投影、跑 conformance——记录状态是一条命令，不是一套仪式。
- **未注册会红**：确定性检查新文件是否在 FILE_INDEX。
- **可反证包**：死指针、编码、复发、溯源 class、常设结论时效。
- **NOW 校验**：NOW 有界、有效 UTF-8、先读可解析，且**最后一条事件之后没有任何文件被改动**（未记录的工作会红）。
- **分层检索**（`search.ps1`）：`all|now|history|files|anchor`——grep 正确的层，而不是把一切都读一遍。
- **邮件**：一步发信、只唤醒的轮询，或完备后台守护（空闲即纯睡眠、不耗 LLM）+ 加锁 + 崩溃恢复 + 状态；运行时产物落在 `_runtime/`。
- **嵌套项目 git 守卫**：pre-commit 拦截「目录级 `git add` 吞掉自带 CLAUDE.md 的嵌套项目」。

这些是帮手，不是对 agent 的命令；是否使用可选。

## 项目暂停

刷新 `## NOW` → 记录「暂停于 YYYY-MM-DD。原因：...」→ CLAUDE.md 状态改 ⏸️。恢复时视 `## NOW` 可能过时，与用户确认。

## 单一事实来源

每个事实只住一个文档。当前状态 → CURRENT_STATUS（`## NOW`）；文件清单 → FILE_INDEX；历史 → `events.log`；锚/铁律 → CLAUDE.md。CLAUDE.md 的一句话状态是唯一允许的冗余；冲突时以 CURRENT_STATUS 为准。

## 铁律的管理

铁律住在 CLAUDE.md。架构/范围变化时新增；一般不删除，标注 `[已不适用: 原因]`。

## 文档生命周期

被替代的文档：首行加 `⚠️ SUPERSEDED BY <路径>`，然后移入 `## 已替代` 或 `_archive/`。

## 可选长期文档

- **`PHILOSOPHY.md`** —— 来自实践的原则：原则陈述 / 催生实践 / 适用范围 / 首次记录日期。是锚层引用的「底层原则」全文之家。
- **`PARKING_LOT.md`** —— 暂缓事项，含复活前置条件。
- **`RUNBOOK.md`** —— 运维重启/续跑状态（任务、源、阈值、命令），区别于文档状态。

## 可选跨项目通信（inbox/outbox）

若存在 `inbox/` 与 `outbox/` 则启用。

**接收**：读未读 → 处理 → 标 `status: actioned`。除 status 字段外不改来信。

生命周期：`unread → read → actioned → awaiting-reply → closed`。需要回复则置 `awaiting-reply`；线程结束置 `closed`。

**发送**：文件名 `YYYY-MM-DD-from-<本项目>-<主题>.md`；YAML `from/to/date/subject/status/priority`；写本项目 `outbox/` 并复制到收件方 `inbox/`。数值写正文（快照优于指针）。交流本身若改变了状态，就记成事件（如 `judgment:set`）或写入 `MAIL_LEDGER.md`——CURRENT_STATUS 是生成物，不能手写。

**发送前自检**：`from:` 是本项目；写进本项目 `outbox/`；复制目标是收件方 `inbox/`；未改收件方内部文档；收件方协议已启用；**收件方能否在不了解我的上下文的情况下读懂这封信**（知识的诅咒自检——把相关快照写进正文，而不是给指针）。

**邮件账本（可选）**：消息量大时维护 `MAIL_LEDGER.md`，记录谁/何时/状态/待回。
