# Doc Harness — 恢复

当上下文为空或用户说「恢复」时，显式、可验证地恢复状态。`resume` 证明 agent 已正确接手——不只是读文件。

## 何时使用

- 「继续这个项目」「恢复」「上次做到哪里」。
- 空上下文 + 核心文件齐全 → 先于任何动作自动触发。
- compact 恢复之后（用户不在场）。

## 模式

- **interactive**（默认）：呈现恢复报告，与用户确认。
- **auto**（`--auto`）：不询问，直接应用新鲜度决策树；若恢复出的现实与投影不符，把差异记为事件（绝不手改 CURRENT_STATUS）。

## 阶段 A：执行接手链

**步骤 0 — 身份**：读 `CLAUDE.md` 顶部 AGENT IDENTITY LOCK。声明「我是本项目的代理，职责范围是……」。

**步骤 1 — 稳定锚 + 声明**：读 `CLAUDE.md` 的稳定锚（框架锚、铁律、底层原则）。然后**声明**当前任务落在哪一层、边界在哪（取自框架锚）——要说出来，不只是读。读会滑过去，说出来才被自己听见。

**步骤 2 — 当前状态**：从 `events.log` 读当前状态（用 `tools/project.ps1` 或 `Get-DocState`），并校验 `CURRENT_STATUS.md` 是新鲜投影（跑 `tools/conformance.ps1`，它会标 `projection-stale`）。不要只信可能过期的 `CURRENT_STATUS.md`。

同时读**否定台账**（`dead-end:set` 事件）里与活跃单元相关的条目——避免重走已被标记为死路的路。

**步骤 3 — 先读**：只读 `## NOW` 的「先读」清单指向的文件。

**步骤 4 — 边缘扫描**：
- NOW 新鲜度：最后刷新是今天吗？
- 收件箱未读：有 `status: unread` 吗？
- 编码/行数：`## NOW` 是否完整、≤ 约 30 行？
- 中继一致：NOW 与活跃工作面 / `events.log` 是否一致？

## 阶段 B：恢复报告（7 节）

1. 身份与范围。
2. 现在快照（在办、下一步、先读、关键判断）。
3. 活跃前沿（哪些单元在做、横跨哪些部分）。
4. 最后收口的单元（来自工作面 / `## Recent History`，二者都是 `events.log` 的投影）。
5. 未读信号（收件箱、漂移）。
6. 边缘条件（NOW 过期、编码、中继不一致、障碍）。
7. 就绪自评（继续 / 等待 / 先 check|sync|flush）。

## 阶段 C：理解验证（5 问，用自己的话）

1. 当前工作试图达成什么？（不是整个项目）
2. #1 下一步是什么、被什么阻碍？
3. 最后收口的是哪个工作单元？
4. 有需要先处理的未读信号吗？
5. 未经用户确认继续是否安全？（≤7 天新鲜 + 无边缘条件 + 未暂停 = 安全）

任一失败则重读并重试一次；仍失败则标记理解不完整。

## 阶段 D：决策

- **交互**：呈现报告 + 验证；问「与你的理解一致吗？按 #1 继续，还是有变化？」
- **自动**：≤7 天新鲜 + 无边缘条件 + 未暂停 → 继续；否则写「等待用户确认」。

## 输出格式

```
═══════════════════════════════════════
  Doc Harness — 恢复
  项目: [名称]   日期: YYYY-MM-DD HH:MM   模式: interactive/auto
═══════════════════════════════════════
── 阶段 A: 接手链 ──
身份: ...   锚: 已读   NOW: 已读   先读: [文件]   边缘: [列表]
── 阶段 B: 恢复报告 ──
§1 身份 ... §7 就绪 ...
── 阶段 C: 验证 ──
Q1..Q5 → 通过/失败   总体: ...
── 阶段 D: 决策 ──
...
═══════════════════════════════════════
```
