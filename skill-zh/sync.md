# Doc Harness — 同步

修复漂移、刷新持久状态，使其与现实一致。与 `check`（只诊断）不同，`sync` 会改文件。

## 模式

- **interactive**（默认）：工作单元折叠、归档、原则提取前先询问。
- **auto**（`--auto`）：无需询问执行安全修复。

## 步骤 1：漂移扫描（只读）

| 检查 | 动作 |
|------|------|
| 未注册文件 | 磁盘文件 vs FILE_INDEX（递归 + 子索引裁剪） |
| NOW 新鲜度 | `## NOW` 最后刷新不是今天？ |
| NOW 行数/编码 | >30 行？乱码？ |
| 入口唯一 | AGENTS.md 是薄指针？过时？ |
| 工作单元事件 | 状态已变但 `events.log` 里没有对应事件的单元？ |
| events.log 长度 | ≥5000 行（值得考虑压缩）？ |
| 收件箱 | 未读 / 归档到期 / 畸形 / 未记录 outbox |

## 步骤 2：安全自动修复

1. 注册未注册文件（按类别启发式；必要时建 `## 未分类`）。
2. 通过记录描述现实的事件（`next:set` / `read-first:set` / `judgment:set`）刷新 `## NOW`，再用 `tools/project.ps1 -Write` 重投影；更新 CLAUDE.md 一句话状态、FILE_INDEX 日期。
3. 收件箱整理：归档过期 actioned、隔离畸形。
4. 若有工作单元已收口，追加它的 `unit:close` 事件**并带证据**（`evidence=<路径> class=root|decision|reported`）后重投影（交互模式先问）。证据正是让收口可反证的东西。

## 步骤 3：收口记录

把工作面与现实对照：现实中已完成、投影里仍是 `[active]`/`[future]` 的单元，需要补它的事件（`unit:close` 带证据，或 `unit:pause`）；现实中在做、却从未 activate 的单元，需要 `unit:activate`。每修一个单元就是追加一行——绝不重写日志。

## 步骤 4：events.log 压缩（罕见，仅交互）

`events.log` 每次状态变更才加一行，不需要例行归档——非常忙的项目一年也就约 5000 行。若真到了那个量级，**压缩是重写而非裁剪**：把原始日志移入 `_archive/events-<YYYY-MM-DD>.log`（作为证据保留），再新建一份日志：为每个被归档的单元写 `unit:open` + 一个终止事件（`unit:close`/`unit:pause`）以复现其终态，随后接上活跃单元的事件。用 `tools/conformance.ps1` 验证投影除预期的历史裁剪外未变。绝不能让 `activate`/`close` 事件对应的 `open` 被归档掉——那会变成解析错误。

## 步骤 5：原则提取（仅交互）

提议把 session 催生的原则记入 `PHILOSOPHY.md` 或提升到稳定锚。auto 模式跳过。
